## Enrollment guide

The [official Gemini voice replication guide](https://ai.google.dev/gemini-api/docs/voice-replication) was checked on 2026-09-28. It requires two recordings of the same adult speaker. The reference clip should contain 10–30 seconds of clean, natural speech. The consent clip must recite Google's exact statement. The Italian statement is shown in Settings and linked to the official guide. Use the same microphone and quiet room for both clips.

1. Launch the native Windows app and open **Settings → Gemini Voice Replication**. Confirm the API status is connected.
2. In **Reference voice**, record 10–30 seconds of your ordinary speaking voice, or choose a local MP3 or WAV. The existing `NebVoiceRegistrations/audio (2)_[cut_21sec].mp3` is a suitable duration candidate; use that file first if its speech is clear.
3. In **Consent**, read the exact displayed Italian statement in a separate recording, or choose an existing MP3/WAV only if it contains that exact statement spoken by you.
4. Select the microphone beside the recording controls; use **Detect microphones** if Windows has not shown device names yet. For hands-free capture, select your wireless headset microphone and press **RECORD MICROPHONE** before moving to a quiet spot. The app measures background noise briefly, waits up to two minutes for sustained speech, then records until you pause (about 2.4 seconds for the reference, 1.8 seconds for consent) or reach 30 seconds. A brief pre-roll keeps the beginning of the first word. **CANCEL WAITING** discards an attempt before speech starts; **STOP RECORDING** ends a speaking clip early. The microphone is monitored locally while waiting, and the waiting interval is cut from the finished audio. Short, quiet background sounds are ignored, but loud or speech-like noises can still trigger capture, so listen to the local preview and choose **DISCARD** if needed. Check the displayed duration and format. The app converts decodable audio locally to mono, 24 kHz, 16-bit PCM WAV. No clips are persisted in app settings.
5. Give the voice a name, check the ownership and consent box, then press **CREATE VOICE**. This sends both audio clips to Google's Voices API with `store: true` and saves the returned `voice_...` ID in local settings. Google's current guide lists a one-year retention period for stateful voices.
6. Open **Console**, verify your replicated voice is selected, and test a short script through the system speakers. Listen for correct identity, intelligibility, and naturalness before using virtual cable routing.

The app does not create the voice, access the microphone, or upload clips on its own. Enrollment and live quality can only be verified with the owner's recordings. A rejected request may mean the phrase was not exact, the speaker verification failed, or project access is unavailable. Retake the clips in the same quiet room and check the [official requirements](https://ai.google.dev/gemini-api/docs/voice-replication).

If Google returns HTTP 500, the response does not tell us whether the failure was inside Google's service or during speaker verification. The [Gemini API error guide](https://ai.google.dev/gemini-api/docs/api-errors) calls 500 an unexpected server error; a [Google developer forum report](https://discuss.ai.google.dev/t/gemini-3-8-voice-replication-post-v1beta-voices-returns-500-internal-with-rest-and-google-genai-2-25-0/184692) documents the same endpoint returning 500 for one recording pair and succeeding with a fresh pair recorded in the same session. Our app disables automatic retries for voice creation so each press makes one enrollment request and shows the original HTTP status. Before another attempt, check whether a voice was saved despite the error.
